# 开发实录 · 观点进化缸

> 用途：记录本项目开发过程中的关键技术决策、踩坑与解法，供复赛迭代与后来者参考。
> 撰写时间：2026-09-13（48 小时冲刺首夜，接入真实凭证后更新）

## 0. 今晚最大的发现：隐藏接口 `question_answers`

**这是本项目最重要的一段开发经验：文档会过时，额度清单才是能力地图。**

1. **起因**：接入 Access Secret 后跑通全部接口，发现真实额度结构与官方文档严重不符（直答 2 次/日而非 100，热榜 2 次/日而非 100）。
2. **线索**：调用免费不耗额度的 `/api/v1/quota`，返回的 `APIID` 清单里出现了一个文档从未提到的 `question_answers`（知乎问题回答，10 次/日）——**有额度项就必然有对应端点**。
3. **探测**：盲猜路径 `/api/v1/content/question_answers`，传 `QuestionID` 返回 `10001: QuestionUrl must be a valid Zhihu question URL`——错误信息直接告诉了我们正确参数名。传 `QuestionUrl=<知乎问题链接>` → 200，返回该问题下真实回答列表。
4. **收尾**：该接口字段极简（`ContentToken/Url/Summary` + `Paging{IsEnd,NextOffset}`），无赞同数。用同题知乎搜索做 **LCS≥20 连续汉字匹配**富化——搜索摘要其实是查询偏置的中段片段（前缀匹配 0 命中，实测教训），只有 LCS 能可靠判定"同一回答"（785 赞同精确归属，不同问题的相似回答会被正确拒绝）。
5. **结果**：原方案"输入问题链接抓取该问题下的回答"从不可行变为**已实现**，产品核心体验升级为真实问题直取。

方法论沉淀：**错误信息是最好的文档；quota 清单是隐藏能力地图；免费接口可以随便探。**


## 0.5 第二个重大发现：直答是问答产品，不是指令执行器（2026-09-13 白天）

**如果说 0 节的教训是「文档会过时」，这一节的教训是「API 的能力类型比它的接口形状更重要」。**

### 现象

上线首夜写的标注管线，是把 `zhida-fast-1p5` 当成一个 JSON 分类器：
system prompt 写「严格只输出 JSON 数组 `[{n,stance,strategy,summary}]`」，
user message 塞进问题标题 + 10 条回答摘要。

第二天复盘四个已构建的生态缸，发现 **40 个物种全部是「中立·数据论证」**——
一个不落。可视化就是一坨同色圆点，产品最核心的概念完全没被呈现。

### 排查

一开始怀疑是额度（实测直答只有 2 次/日，很容易怀疑到这上面）。
但用免费的 `/api/v1/quota` 一查，那几次调用确实计费成功了——**说明请求打通了，是返回内容不对**。

于是花掉当天最后一次额度，写了个探针把**原始响应完整落盘**
（`docs/evidence/zhida-raw-2026-09-13.json`）。结果一目了然：

> 它返回了一篇 1500 字的知乎风格长回答，开头是
> 「# 如何看待于东来发文称胖东来再招员工都是学员性质…」，
> 中间带「（澎湃新闻、大河报等多源报道一致）」这样的检索来源标注。
> **完全没有 JSON，system prompt 像不存在一样。**

**根因**：直答是 RAG 问答 / 检索产品，不是通用 instruction-following 模型。
它从 user message 里认出了那个知乎问题，然后就去回答它了。
官方文档其实写了线索——「当前仅保证 `model/messages/stream` 三个字段的能力语义」，
但没人会把这句话读成「system role 可能被丢弃」。

### 解法：不要逼一个问答模型做判别，改让它做它擅长的事

把「逐条标注」和「整缸解说」拆成两条独立通道：

- **逐条标注 → 本地可解释模型**（`src/annotator.js`，430 行词典 + 规则）。
  零额度、确定性、每个判定带命中证据。
- **整缸解说 → 直答，自然语言提问，不加任何格式约束**。

第二条通道的 prompt 实测下来效果**远超预期**
（`docs/evidence/zhida-explain-2026-09-13.json`）：

```
在知乎问题「{question}」下，目前主要存在哪几种不同立场的观点？
每一派分别靠什么方式说服读者——是摆数据、讲个人经历、调动情绪、
诉诸身份认同、引用权威，还是靠抖机灵？请分派说明，并指出哪一派目前最占上风。
```

它自发返回了结构清晰的 markdown：五个派系各带「代表观点 / 说服方式」，
末尾一个「哪派最占上风」小节，而且**标注了检索来源**（「搜索结果1、5、9」）。
它归纳出的说服方式（摆数据 / 讲个人经历 / 调动情绪 / 诉诸身份认同 / 引用权威 / 抖机灵）
几乎与我们预设的六类生存策略一一对应——这反过来验证了这套分类不是拍脑袋定的。

### 沉淀的方法论

1. **拿到一个 LLM-ish API，先分清它是「指令执行器」还是「垂直问答产品」。**
   判据很便宜：发一次带明确格式要求的请求，看它守不守。比读文档快。
2. **调用成功 ≠ 功能成功。** 额度扣了、HTTP 200、没抛异常，但返回的东西完全不是你要的。
   catch 分支吞掉异常之后，失败会伪装成「降级」静静躺在生产数据里。
3. **所以任何降级路径都必须有分布健康检查。** 现在 `annotateAll()` 会在
   ≥80% 物种落进同一类时挂 `annotationWarning`——
   **让失败变成可见的，比让它优雅地失败更重要。**
4. **排查一定要把原始响应落盘。** 从「标注不对」到「根因确认」只花了一次调用，
   靠的就是不解析、不截断、直接把 raw response 写文件。

### 顺带修掉的设计债

- 放生分析原来也是「要求直答输出 JSON 对象」，同样注定失败。
  改为：数值全部由透明规则模型产出，草稿立场由本地标注器判，直答只追加文字点评。
  `analysisSource` 从 `ai+rule` 改名为 `rule+local` / `rule+local+ai`——
  **旧名字暗示了 AI 参与概率计算，那是不准确的表述。**
- 预构建缸（`prebuilt-tanks.json`）永久有效，不受 24h TTL 约束；
  带 AI 叙事的缓存条目永久豁免 100 条裁剪——那是真实烧掉额度换来的资产，裁掉等于白烧。

## 1. 可行性审查如何改变了产品形态

原方案（`../docs/观点进化缸-项目文档.md`）设想"输入问题链接抓取全部回答 + 真实历史时间轴 + 折叠化石层"。逐项对照知乎开放平台 API 后发现三个根基性缺口：

| 缺口 | 原假设 | API 现实 | 解法（最终状态） |
|---|---|---|---|
| 无"问题→回答列表"接口 | 抓取该问题下所有回答 | 文档内仅有 `zhihu_search` 关键词搜索（≤10 条/次） | **已解决**：实测发现隐藏端点 `question_answers`（URL 直取），叠加搜索 LCS 富化形成双通道 |
| 无历史时序数据 | 拖动时间轴看任意一天 | 所有字段只有当前时点值 + EditTime | EditTime 升序重演"入场"，UI/报告双标注"AI 演化重建 · 非历史记录" |
| 无折叠/删除数据 | 化石层 | 完全不可得 | 整体移除，不做任何虚假声称 |

**经验**：黑客松选题先审数据可得性再定功能边界；"标注推演"（明确声明）与"伪装真实"（评审一戳就破）之间必须选前者。

## 2. API 集成要点（以实测为准）

- **鉴权**：`Authorization: Bearer <secret>` + `X-Request-Timestamp`（秒级），缺一不可。
- **真实额度以 `/api/v1/quota` 实测为准，不要信文档**：本项目账号实测为直答 2/日、热榜 2/日、搜索 10/日、问题回答 10/日、用户数据 1000/日、知识库 500/日。文档写的是"邀测"通用额度（搜索 5000/日等），校园季试用凭证额度小一个到三个数量级。
- **429 不消耗额度**（实测两次 429 后 `TotalUsed` 不变），但 200 + 解析失败会消耗——所以标注只重试一次以下，宁缺毋滥。
- ~~**直答 JSON 输出**~~ / ~~**标注批量化**~~：**这两条已在 0.5 节被推翻**。直答不遵守格式指令，
  `extractJson()` 代码保留但不再是主路径；逐条标注已改为本地零额度模型。保留划掉的原文是为了留下决策轨迹。
- **双层额度守卫**：本地计数 + `zhidaRemaining()`（quota 接口免费，结果缓存 60s）。本地守卫误判好过现场 429。
- **缓存分层（额度防泄漏五道闸）**：
  1. 结果缓存：热榜 12h（2 次/日只够早晚各一次）；生态缸 24h 按问题名+URL 哈希；搜索 6h；question_answers 6h；放生分析 1h（问题+草稿哈希）；
  2. **并发去重**：`dedup(key, fn)` 保证同 key 并发请求只发一次上游调用（实测 3 个并发仅 1 次构建，全部返回同一结果）——双击/前端重试不再双倍消耗；
  3. **磁盘持久化**：生态缸缓存写入 `server/data/eco-cache.json`，服务重启不丢已消耗额度换来的数据（当天多次重启的实测教训）；
  4. 双层直答守卫：本地计数 + `zhidaRemaining()`（quota 接口免费，结果缓存 60s）；
  5. stale-while-error：热榜耗尽时官方返回**空列表而非报错**——必须显式判空并降级为演示热榜+警告横幅，否则前端白屏。
- **搜索相关性**：`zhihu_search` 返回的是"相关内容"而非"同题回答"，用查询词与标题的字符 2-gram 重现率过滤（阈值 0.25），不足 3 条时放宽取 Top 6——宁可样本少，不要跑题的"物种"。
- **跨接口同一回答判定**：`question_answers` 与 `zhihu_search` 的内容 ID 完全不同域（实测 token 匹配 0 命中）；搜索摘要是查询偏置的中段片段（前缀匹配 0 命中）。最终用 **LCS≥20 连续汉字** 判定，实测精确命中且能拒绝不同问题的相似回答。

## 3. 前端技术决策

- **d3-force 而非手写力导向**：直接用官方力模拟；**同步跑 300 tick 取终态**而非逐帧物理动画——生态图是"重算后呈现"的分析视图，不是粒子玩具。
  UI 改版后在此之上加了一层 **180ms 的 rAF 补间**：布局仍是同步算出终态，只是从上一状态缓动过去（新节点从 r=0 长出）。
  这样既保留了零延迟重算，又让"生态在重算"这件事肉眼可见——一个叫「进化缸」的产品完全静止是概念上的失分。
  运动只由用户操作触发且 ≤200ms，不做循环动画。
- **自绘 SVG 报告而非 html2canvas**：报告 SVG 全部由代码生成（无外部图片/字体），序列化 → Image → canvas → PNG 全程同源，规避 html2canvas 的跨域污染与样式还原度问题，且产物在知乎侧清晰可读。
- **能量模型**：圆面积 ∝ 能量（`r = 18 + 46·√(energy/max)`），环境干预四参数（推荐权重/时近度/情绪气候/大V加权）纯前端重算，`computeEnergy()` 单函数可解释。

## 4. 生存概率模型

`P = 100 × (0.35×策略蓝海度 + 0.25×立场差异化 + 0.20×权威压力缓冲 + 0.20×互动基础度)`

**2026-09-13 重构后：概率完全由这个公式产出，AI 不参与数值计算。**
原设计是「直答预测值与规则值按 6:4 混合」，但 0.5 节证明直答不会返回可解析的数值；
更重要的是，**一个不可复现、不可解释的数字混进公开公式里，会让整个公式失去意义**。
现在的分工是：
- 数值（存活概率、压制来源、风险、杂交建议）→ 规则模型，公式写在 UI 上，评委可当场复算；
- 草稿自身的立场/策略 → 本地标注器（与缸内物种同源，保证可比）；
- 直答 → 只追加一段自然语言点评「这条回答会遭到哪些反驳」，可缺省。

`analysisSource` 取值相应改为 `rule+local` / `rule+local+ai` / `rule-only-demo`——
旧的 `ai+rule` 这个名字本身就在暗示 AI 参与了概率计算，是不准确的表述。

## 5. 踩坑记录（环境与工具链）

1. **沙箱 shell 的 stdout 吞噬**：本机 PowerShell 工具对原生命令的 stdout 经常返回空（`Write-Output` 也可能被吞），但文件写入可靠。**解法**：所有需要"看结果"的验证一律落盘再 Read（`e2e-test.cjs` 用 fetch 请求 + `writeFileSync` 写结果文件）。
2. **npm.cmd 被 cmd.exe 包装**：PowerShell 工具禁止 cmd.exe，`npm.cmd` 直接调用被安全拦截。**解法**：用 node 直接跑 `node_modules/npm/bin/npm-cli.js`。
3. **默认 registry 超时**：外网 registry 在本环境 ETIMEDOUT（280s 不够）。**解法**：`--registry=https://registry.npmmirror.com` + 后台运行 + `run-npm.cjs` 诊断器（spawnSync 输出落盘，绕开 PowerShell 流包装）。
4. **PowerShell `*>` 重定向污染日志**：原生命令 stderr 会被 PS 5.1 包成 NativeCommandError 记录，日志里混入"所在位置 行:445"等伪内容。**解法**：一律用子进程语言（node）自己的文件 IO，不用 shell 重定向收集诊断。
5. **Port 冲突/进程清理**：dev 用 `node --watch`，注意 Windows 下后台 task 停止后端口释放有延迟，重跑前先 `netstat` 确认 8787/5173。

## 6. 交付前的诚信检查（每次改版都要过一遍）

- [ ] 时间轴与放生报告的"AI 重建/预测"徽标仍在（重构时最容易丢）
- [ ] 直答失败路径真实可触发（临时改坏 secret 测一次降级 UI）
- [ ] 演示模式徽标在 status 接口失败时也正确显示（fail-closed，不误标"实时"）
- [ ] 凭证零泄露：`git status` 干净、前端 bundle 中 grep 无 secret、截图不含 .env
- [ ] **标注分布没有退化**：随便开两个缸，看立场/策略是不是又全落一类（`annotationWarning` 应为空）
- [ ] **低置信物种有角标**：置信度 < 0.15 的物种界面上要看得出来，不能伪装成确定判断
- [ ] 一键跑 `node tools/compliance-check.mjs --dist`（凭证泄漏 / 三处诚信标注 / 依赖变更，全脚本判定）

## 7. 后续路线（V2 候选，按优先级）

1. **知乎 OAuth 登录** → "我的观点画像"：用户授权后把自己的创作数据放进缸里对比生态位。
   `user_data` 实测 **1000 次/日**（不是文档里的 10,000，但仍是所有能力里最充裕的一个，评委可以随便玩）。
   赛事官方明确「推荐接入 OAuth，登录人数会作为人气奖评定之一」，是性价比最高的加分方向。
   前置条件：活动页创建项目拿到 `app_id`/`app_key` + 已部署的公网回调地址。
2. **定时快照累积** → 真实纵向数据的时间轴（预采集 2-3 个热榜问题，每小时一次）
3. **全网搜索补充通道** → `global_search`（单次 ≤20 条）扩大样本
4. **故事/知识内容 API** → 跨次元叙事彩蛋（免鉴权接口，低成本加分项）
