## 2. 【最高优先级】修复能量标度 bug —— 现在 90% 的节点都被压成最小圆

### 现象

打开真实缸（10 个物种），只有 1 个圆是大的，其余 9 个全是同样的最小尺寸。
生态缸看起来像一颗恒星加九颗尘埃，完全体现不出「能量竞争」。

### 根因

`app/web/src/lib/force.ts` 的 `computeEnergy()`：

```js
const maxVotes = Math.max(1, ...all.map((x) => x.votes ?? 0));   // ← 算了但根本没用
const maxHeat  = Math.max(1, ...all.map((x) => x.heatRank ?? 0));
const votesPart = s.votes ?? (s.heatRank ?? 0) / maxHeat;        // ← 单位不一致
```

`question_answers` 接口**不返回赞同数**，只有被知乎搜索 LCS 匹配上的少数条目才有。
于是同一个数组里混着两种量纲：

- 富化成功的节点：`votesPart = 880`（赞同数原值）
- 未富化的节点：`votesPart = heatRank / maxHeat ∈ (0, 1]`

`buildLayout` 里 `r = 18 + 46·√(energy/maxEnergy)`，`maxEnergy ≈ 880`，
所以所有未富化节点的 `√(1/880) ≈ 0.034` → 半径全部贴在下限 18~19px。

### 要求的修法

1. **两种来源各自归一化到 0..1 再比较**：
   - 有赞同数：`s.votes / maxVotes`
   - 无赞同数：`s.heatRank / maxHeat`
   （`maxVotes` 已经算好了，现在只是没用上。）
2. **未富化的节点要在视觉上可辨认**——不能让用户以为那个尺寸是真实赞同数换算的。
   在节点内圈加一道**细虚线内环**（`strokeDasharray`，1px，低透明度），
   图例增加一项：`虚线内环 = 该回答无公开赞同数，按热序近似`。
3. **详情卡**已经写了「（按热序近似）」，保留。
4. **不要改变有赞同数节点之间的相对大小关系**（那是真实数据，必须保真）。

### 验收

用真实缸（`node app/server/src/index.js` 起服务后打开首页点任意「缸已就绪」条目）
截图，**10 个节点的半径要有明显层次**，不再是「1 大 9 小且 9 个一样大」。

## A1. 色轴自适应问题类型（新增，优先级高）

**问题**：9 个预构建缸里仍有 5 个报「立场退化：中立占 8~10/10」。
抽查后确认**告警大体属实**——这些是「为什么…」「如何…」型问题，
回答本来就是在解释而不是在站队，**「立场」这个轴对它们根本不成立**。

结果就是这些缸渲染出来是一片灰，既不好看，概念上也是错的
（把「这个维度不适用」画成了「所有物种都是中立物种」）。

**决策：颜色轴按问题类型自适应。**

服务端已经有 `classifyQuestion()`（返回 `judgement` / `why` / `howto` / `open`），
但目前没有透出给前端。**你不能改服务端**，所以前端自己判：
用与服务端同样的句式规则对 `eco.question` 做一次轻量判定
（`如何看待` `怎么看` `是不是` `该不该` `值不值` `算不算` `吗？` → 判断型；
`为什么` `为何` `原因` → 归因型；`如何…` `怎么办` `有哪些` → 求解型；其余开放型）。
**把这段判定单独抽成一个带注释的小函数**，并注明它与服务端 `annotator.js`
的 `QUESTION_PATTERNS` 是同一套规则的前端副本，改动要同步。

| 问题类型 | 节点填充色编码 | 图例主标题 | 圆内符号 |
|---|---|---|---|
| 判断型 / 开放型 | **立场**（现状不变） | `颜色 = 观点立场` | 生存策略 |
| 归因型 / 求解型 | **生存策略** | `颜色 = 生存策略（本题不预设对立立场）` | 立场首字（若立场非中立）否则留空 |

归因型下需要一套 6 色的**策略配色**（同样色相间隔 ≥45°、低饱和半透明、亮描边）。
详情卡与 HUD 芯片里两个维度都照常显示，只是**颜色编码的对象换了**。

在缸顶部加一行小字说明当前色轴，例如：
`本题为归因型提问，不预设对立立场 —— 颜色按生存策略编码`

**这条要讲清楚**：它不是把不好看的数据藏起来，而是**换一个对这类问题成立的维度**。

## A2. 「零证据策略」渲染成未识别态（新增）

标注器目前对**完全没有命中任何策略特征**的回答，会兜底给一个「数据论证」。
这是「数据论证泛滥」的残留来源（清朝人口缸 10/10 数据论证，其中约一半是兜底）。

我决定**不加第七类标签**（污染分类体系），改由前端如实渲染：

判定条件：`s.evidence.strategy.length === 0`
或 `s.evidence.strategy[0].term === '特征不足'`。

这类节点：

- **不画策略符号**（圆内留空）
- 圆的外描边改为**细虚线**（与 A2 的「无赞同数」内环区分开：外描边 vs 内环）
- 详情卡的策略行显示 `未识别（无显著策略特征）`，不显示假的「数据论证」
- 图例加一项：`虚线外描边 = 未识别出显著生存策略`
- HUD 或缸顶统计里加一个 `未识别 N` 的计数

**为什么要做**：一个能诚实说出「这条我判不了」的模型，比一个把所有东西都塞进
六个格子的模型更可信。这也是产品说明里「可解释」叙事的一部分。

## A3. 关于 `annotationWarning` 的展示措辞

服务端现在的告警文案是「立场特征稀疏，多数物种落入同一类，标注可信度低」。
这句话在**归因型问题**上是误导的——那里 90% 中立可能完全正确。

**前端按 A1 的问题类型分情况展示**：

- 判断型 + 有告警 → 原样显示服务端文案（这时确实是标注可信度问题）
- 归因型 / 求解型 + 立场告警 → 改显示
  `本题为归因型提问，回答以解释为主而非站队 —— 立场维度参考价值有限`
  （不显示「标注可信度低」，因为那不是事实）
- 策略告警 → 一律原样显示

这条一定要做对。**把「维度不适用」说成「模型判不准」，是对自己产品的错误指控。**
