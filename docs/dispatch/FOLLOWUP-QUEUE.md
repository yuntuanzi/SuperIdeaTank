## F1 ｜ 热榜必须磁盘持久化（P0，会在评审当天出事）

**问题**：`hotCache` 只在内存里（`zhihu.js` 的 `const hotCache = { data: null, ts: 0 }`），
TTL 12 小时，但**进程一重启就清空**。

而 Render 免费档**15 分钟无请求就休眠**，评审期两天里服务会反复冷启动。
每次冷启动后第一个访客都会触发一次真实 `hot_list` 调用——而热榜额度只有 **2 次/日**。
**第三个访客开始就只能看到演示热榜。**

**要做**：
1. 热榜结果与 `eco-cache.json` 一样落盘（`app/server/data/hot-cache.json`），启动时载入
2. 再准备一份**随仓库提交的热榜快照**（`app/server/data/hot-snapshot.json`）作为最终兜底，
   界面上如实标注「热榜快照 · 采集于 YYYY-MM-DD HH:MM」，而不是笼统的「演示数据」
3. 同一处理也适用于 `searchCache` / `qaCache`（目前同样是纯内存）

**归属**：Codex（服务端）｜**为什么不现在做**：Codex 正在改同一批文件

产出 `prebuilt-tanks.json`。**零额度消耗，可以反复重跑。**

**归属**：Codex（紧接当前任务）

## F5 ｜ 演示模式的措辞要改（P2）

现在未配置凭证时前端显示「演示数据 · 未接入开放平台」。
但重构后即使**接入了**开放平台，直答额度耗尽时也会有降级。
两种状态不能共用一个徽标，否则评委会误以为整个产品没接真实数据。

建议三态：
- `实时 · 知乎开放平台`（有凭证 + 本次数据来自实时调用）
- `缓存 · 采集于 {时间}`（有凭证 + 命中缓存/预构建缸）← **评审当天大部分时候是这个**
- `演示数据集`（无凭证）

**归属**：Kimi（并入 F3）
