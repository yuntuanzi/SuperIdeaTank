# A. 可行性审查报告

> **2026-09-13 深夜重大更新**：接入凭证后实测发现，开放平台额度清单中存在文档未记载的 `question_answers`（知乎问题回答）接口——传入问题 URL 可**直取该问题下的真实回答列表**。原方案最核心的"按问题抓回答"缺口已实际闭合，通道 A（URL 直取 + LCS 富化）已实现并通过真实数据验证。本文 A2 表格保留原始审查过程，缺口 1 的结论已由"重构"升级为"**已解决（双通道）**"。

## A1. 审查结论（总评）

**判定：核心概念成立，可参赛；原方案的数据根基需要重构。**

原方案「把知乎问题变成可观察、可干预、可放生的观点生态系统」的概念、卖点与产品机制设计完整且与知乎社区生态高度契合。但方案撰写时的数据假设（"抓取该问题下所有回答 + 完整历史时间序列 + 折叠痕迹"）超出了知乎官方开放 API 的实际能力边界。按原方案直接开发，会在 Demo 现场出现核心数据无法获取的硬伤。

经逐项审查：原方案 10 项产品机制中，**5 项可直接落地，4 项需降级重构，1 项必须移除**。重构后的方案完整保留"生态缸"的核心体验（围观 → 剖析 → 放生 → 干预 → 报告），且全部数据来自官方 API 真实返回，评审可溯源。

## A2. 逐项能力映射（原方案 vs 官方 API 现实）

| # | 原方案设想 | 官方 API 实际能力 | 判定 | 处理方式 |
|---|---|---|---|---|
| 1 | 输入**问题链接**，抓取该问题下**所有**回答 | 官方 API **没有**"问题 ID → 回答列表"接口。`zhihu_search` 为关键词搜索，单次最多返回 10 条相关回答/文章（含赞同数、评论数、时间、权威等级、精选评论） | ⚠️ 重构 | 改为"输入问题标题/关键词 → 搜索汇聚回答样本"，样本即物种基底 |
| 2 | 拖动时间轴看**任意一天**的真实生态剖面 | 所有接口只返回**当前时点**数据；`EditTime` 仅为发布/最后编辑时间，无历史赞同曲线 | ⚠️ 重构 | 改为"当前快照 + AI 演化重建叙事"，界面明确标注"AI 重建，非历史记录" |
| 3 | 被折叠/删除回答的痕迹 → "化石层" | 官方 API **完全不提供**折叠、删除数据 | ✗ 移除 | 改为"边缘物种"：发布早（EditTime 早）且赞同极低的回答，作为生态压力的可视化素材，不做虚假"化石"声称 |
| 4 | 作者影响力 = 粉丝数 + 领域标签 | 无任意作者的粉丝数；搜索结果提供 `AuthorityLevel`（权威等级 1-4）+ `AuthorBadge` 认证标识 | ⚠️ 降级 | 影响力权重改用 AuthorityLevel + 认证状态，语义为"权威度"，不声称粉丝数 |
| 5 | 收藏数（"收藏是迁徙"） | 搜索结果**无收藏数字段**（收藏数仅存在于本人/授权用户数据 API） | ✗ 移除 | 迁徙隐喻改由评论数（互动）承担，或删除该生态位 |
| 6 | 评论区高赞评论 | `CommentInfoList` 提供精选评论（约 1-2 条/回答） | ✓ 保留 | 直接使用，作为"共生关系"证据链 |
| 7 | 热榜 = 气候突变 | `hot_list` API 完整支持（Top 30，含标题/链接/摘要） | ✓ 保留 | 直接使用 |
| 8 | 放生实验 + 生存预测报告 | 直答 API（`zhida-thinking-1p5` 深度思考档）+ 前端规则概率模型 | ✓ 保留 | **核心亮点功能**，但必须标注"AI 模拟预测"，不得暗示真实数据回流 |
| 9 | 环境干预（4 类参数实时重算） | 纯前端规则引擎可实现，不依赖额外 API | ✓ 保留（降级） | 保留 4 个干预维度，作为可解释的本地模拟，实时重算 |
| 10 | 生态报告一键导出分享 | 纯前端 SVG/canvas → 图片导出 | ✓ 保留 | 保留 |

# B. 重构后的实施文档

## B1. 项目定位

**一句话**：把每一个知乎问题变成一个可观察、可干预、可放生的"观点生态系统"——像生物学家一样围观知乎。

**重构后的产品副标题**（体现数据诚实）：
> 基于知乎开放平台实时数据 + AI 演化推演的观点生态可视化实验场。

**核心差异**（保留原方案表格，修正表述）：
- 已有产品回答"我该看什么"；观点进化缸回答"**观点为什么活下来**"。
- 用户角色从"读者"升级为"生态学家、干预者、放生者"。

## B2. 赛道选择论证

三大赛道：🧠 灵魂匹配局（社区连接）、📚 知识炼金场（知识生产）、🎮 跨次元游乐场（游戏与互动叙事）。

**推荐赛道：📚 知识炼金场**，理由：
1. 官方探索方向明确包含"**观点提炼、观点比较、信息整理与内容共创，帮助用户建立理解，形成判断**"——观点进化缸正是把问题下的讨论转化为"观点物种图谱 + 生存策略排行 + 生存预测"的结构化知识产品；
2. 产品产出（生态报告图）本身是可分享的知识内容，形成"内容共创"闭环；
3. 对应单项奖"最佳学习工具奖"。

备选：🧠 灵魂匹配局（"面向社区讨论场景的 AI 社交辅助与**表达建议**"——放生报告的杂交建议本质是表达建议）。若团队希望冲击"最佳社交创新奖"可选此赛道。**最终以提交时活动页面赛道描述为准。**

## B3. 用户与核心场景

| 用户 | 场景 | 价值 |
|---|---|---|
| 旁观型知友 | 围观热榜问题的观点厮杀 | 看懂"为什么这条回答能赢" |
| 创作型知友 | 发回答前"放生"试水 | 获得生存预测 + 改写建议（表达建议） |
| 内容研究者/运营 | 对比不同问题的策略有效性 | 理解叙事策略与生态位的匹配规律 |

**评委 3 分钟体验路径**（Demo 设计主线）：
打开首页 → 热榜选一个问题 → 一键生成生态缸（实时调用官方 API）→ 拖动演化时间轴 → 调整环境参数看生态重算 → 放生一段自己的回答 → 收到生存预测报告 → 导出生态报告图。

## B4. 功能规格（V1 交付范围）

### F1 热榜选题台（✓ 原样保留）
- 数据：`hot_list`（服务端缓存 1 小时）。
- 交互：热榜卡片列表 → 选择问题进入生态缸构建。

### F2 生态快照（⚠️ 重构后保留）
- 输入：问题标题（自动填充自热榜，或手输任意问题关键词）。
- 处理：`zhihu_search`（count=10）→ 按 Title 相关性过滤 → 每条回答由直答批量标注两个维度：
  - **观点物种**：支持 / 反对 / 中立 / 解构 / 反讽 / 补充
  - **生存策略**：数据论证 / 情绪共鸣 / 故事叙事 / 身份站队 / 抖机灵 / 引用权威
- 输出：物种卡片（赞同数 = 能量值，评论数 = 繁殖度，权威等级 = 体型，精选评论 = 共生证据）。
- 降级：直答失败时展示"未标注"原始数据，不编造。

### F3 生态缸可视化（✓ 新增核心载体）
- 力导向图：每种观点物种 = 一个种群聚落，大小 = 能量（赞同数），颜色 = 立场，连线 = 共生（精选评论互动）与竞争（同物种互斥）。
- 纯前端 SVG/Canvas 实现。

### F4 演化时间轴（⚠️ 重构后保留，强标注）
- 交互：拖动时间轴，回答按 `EditTime` 排序逐步"入场"，生态图随之演化。
- 关键标注：时间轴顶部固定徽标"**AI 演化重建 · 非历史记录**"；产品说明中主动声明数据为当前快照 + 推演。
- 每个时间点由直答生成一句"生态剖面"叙事（复用标注缓存，仅首次构建时调用）。

### F5 放生实验（✓ 原样保留，核心亮点）
- 输入：用户撰写的一段回答（或 AI 草稿）。
- 处理：直答 `zhida-thinking-1p5` 分析 + 前端规则概率模型：
  - 观点物种归类、与现有种群的竞争/共生关系；
  - 存活概率（0-100%，规则模型基于能量分布 + 权威度 + 策略匹配度计算，公式透明可解释）；
  - 会被哪个物种压制、吸引什么评论、折叠风险（基于低赞同样本的统计示意）；
  - **杂交建议**：具体到"加入个人故事 / 补充数据源"的可操作改写。
- 输出：生存预测报告卡片。
- 诚信标注：报告角标"AI 模拟预测，非平台数据"。

### F6 环境干预（✓ 保留，降级为本地模型）
- 4 个参数开关：推荐算法权重（高赞优先/新答优先）、时间窗口、情绪气候（理性/情绪）、权威加权（大V加权/匿名平权）。
- 实现：纯前端规则引擎重算能量分布与存活概率，实时刷新生态图。零 API 消耗。

### F7 生态报告导出（✓ 原样保留）
- 内容：物种进化叙事、生存策略排行榜、关键转折点、放生实验结果。
- 形式：前端渲染 → 导出长图，附"由知乎开放平台数据生成"水印与原问题链接。

### 砍线清单（明确不做，防止范围失控）
- ~~折叠/删除"化石层"~~（API 无数据，虚假声称风险）
- ~~作者粉丝数~~（无接口）
- ~~收藏数维度~~（无字段）
- ~~真实发布回答并追踪~~（开放平台无发布接口；"放生"仅为 AI 预测）
- ~~OAuth 登录 + 个人观点画像~~（V2 预留，V1 不做，控制 38 小时风险）

## B5. 技术架构

```
┌─────────────── 前端（React + TS，静态托管）───────────────┐
│  热榜选题台 │ 生态缸力导向图 │ 演化时间轴 │ 放生面板 │ 报告导出 │
└──────────────────────────┬───────────────────────────────┘
                           │ HTTPS (仅 JSON)
┌──────────────────────────▼───────────────────────────────┐
│  后端（Node.js 轻量 API 层，凭证唯一持有方）                 │
│  • /hot        → 热榜缓存（1h TTL）                        │
│  • /ecosystem  → zhihu_search + 直答批量标注（结果缓存）     │
│  • /release    → 直答 thinking 放生分析（配额守卫）          │
│  • /quota      → 额度查询透传（前端展示余量）                │
└──────┬──────────────┬──────────────┬─────────────────────┘
       ▼              ▼              ▼
  知乎搜索 API    知乎热榜 API     知乎直答 API
  (5000/日)       (100/日)        (100/日)
```

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | React + TypeScript + Vite，可视化用原生 SVG 力导向（自实现，~200 行） | 生态图交互定制性强，D3 全量引入不必要 |
| 后端 | Node.js (Hono/Express)，单进程内存缓存 + JSON 文件持久化 | 38 小时内零运维；够用 |
| AI | 直答 `zhida-fast-1p5`（批量标注，便宜快）、`zhida-thinking-1p5`（放生分析，深度） | 官方指定能力，评审加分点 |
| 部署 | 前端 Vercel / 后端 Lighthouse（用户现有服务器）或同域一体化部署 | 公网可访问为硬性要求；双预案 |

**安全红线**（赛事规则）：Access Secret 只存后端环境变量 `ZHIHU_ACCESS_SECRET`；不进前端代码、URL、日志、截图、视频、代码仓库。

## B6. API 集成规格

| 接口 | 端点 | 调用时机 | 缓存 |
|---|---|---|---|
| 热榜 | `GET developer.zhihu.com/api/v1/content/hot_list` | 服务端每 60 分钟 | 内存 TTL 1h |
| 知乎搜索 | `GET /api/v1/content/zhihu_search?Query={标题}&Count=10` | 用户构建生态缸 | 24h（按问题名哈希） |
| 直答-标注 | `POST /v1/chat/completions`（`zhida-fast-1p5`，批量 10 条，要求 JSON 输出） | 首次构建生态缸 | 与缸绑定持久化 |
| 直答-放生 | 同上（`zhida-thinking-1p5`） | 每次放生 | 不缓存（个性化） |
| 额度 | `GET /api/v1/quota` | 每小时 | 15min |
| 鉴权 | Header：`Authorization: Bearer <secret>` + `X-Request-Timestamp: <秒级时间戳>` | 全部 | — |

**错误处理**（赛事检查项）：接口失败/额度耗尽/空数据均需真实错误提示与降级 UI；`30001` 频率限制 → 提示稍后重试；直答 JSON 解析失败 → 重试 1 次后降级为"未标注"。

## B9. 原方案 → 落地方案 速查表
