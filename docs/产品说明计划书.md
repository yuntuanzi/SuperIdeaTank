## 一、核心创作思路

### 1.1 我们看见的「知乎另一种样子」

知乎表面是问答社区，实质是**观点的自然选择场**。
一个问题下几十上百条回答在争夺同一种稀缺资源——注意力。赞同是能量、评论是繁殖、权威是体型、热榜是气候突变。最后留在顶部的高赞回答，**不一定是最正确的，而是最适应当时生态位的那个物种**。

但今天知乎只把结果给你——高赞排在最上面。看不见的是：
- 为什么是**这一条**活下来？它靠的是数据、故事、情绪，还是身份认同？
- 同一个观点，换一个问题、换一个时间点，还能不能活？
- **我**现在写一条回答扔进去会怎样？我自己又属于哪种「物种」？

### 1.2 我们的解法：可观察、可干预、可放生、可画像

| 能力 | 在产品中的位置 | 用户得到什么 |
|---|---|---|
| 🔬 **观察** | 每条回答 = 一个物种，圆面积 = 能量，颜色 = 立场，圆内符号 = 生存策略，描边粗细 = 权威等级 | 一眼看清「这个问题的观点地图」 |
| ⏱ **回放** | 拖动时间轴，回答按发布时间依次入场 | 看懂「这个生态是怎么长成现在这样的」 |
| 🎛 **干预** | 四个参数开关：推荐权重 × 情绪气候 × 大V加权 × 时近度 | 同题换规则，胜出物种当场易主——**亲手验证「平台规则塑造观点」** |
| 🐟 **放生** | 写一段自己的回答，扔进当前缸里 | 拿到存活概率 + 压制来源 + 具体到句子的「杂交建议」 |
| 🪞 **画像** | 授权知乎账号，读用户自己的公开创作 | 用户**自己**属于哪种观点物种、主导立场与策略是什么 |

这五条能力构成了从「缸里的别人」→「缸里的生态」→「我自己的回答」→「我自己的物种」**完整闭环**。

### 1.3 我们和已有产品的根本差异

| 维度 | 摘要 / 推荐 / 舆情分析 | 观点进化缸 |
|---|---|---|
| 核心对象 | 内容本身 | 观点之间的**生态关系** |
| 时间维度 | 静态快照 | 入场演化 + 参数化推演 + 用户历史 |
| 用户角色 | 读者、消费者 | 生态学家 / 干预者 / 放生者 / 自我分析者 |
| AI 的作用 | 总结、推荐 | 结构化标注 + 模拟预测 + 综述解说 + 自我画像 |
| 回答的问题 | 「我该看什么？」 | 「**观点为什么活下来？以及我是哪种物种？**」 |

它不是推荐系统，不是舆情分析，不是 AI 辩论。它是**观点生态的显微镜 + 模拟器 + 实验缸 + 用户自画像**。

## 二、目标用户与评委 3 分钟体验路径

### 2.1 三类目标用户

| 用户 | 痛点 | 在本产品中得到什么 |
|---|---|---|
| **围观型知友** | 想知道这个争议问题里「几派在打仗、谁在赢、赢在哪种策略」 | 生态缸一眼看清 |
| **创作型知友** | 花两小时写完发出去石沉大海，事后不知道为什么 | 放生实验给出存活预测 + 具体到句子的改写建议 |
| **自我分析型知友** | 想知道「我在知乎生态里属于哪种物种」 | 授权后读本人公开创作，用同一套「立场×策略」模型做自画像 |

### 2.2 评委 3 分钟体验路径（针对 25% 完成度权重）

```
① 打开 https://zh.starsalt.cc → 13 个预构建生态缸 / 144 个物种 / 约 27% 带真实赞同数
   ↓  点任意一条标「缸已就绪」的问题 → 零额度、秒开
② 生态缸渲染：圆面积=能量 · 颜色=立场 · 圆内符号=策略 · 描边粗细=权威等级
   ↓  拖动「演化时间轴」滑杆 → 回答按发布时间依次入场
③ 切到「环境干预」标签 → 调四个参数（推荐权重 / 情绪气候 / 大V加权 / 时近度）
   ↓  缸图实时重算，优势物种当场易主
④ 切到「放生实验」→ 写一段自己的回答 → 拿到 0-100% 存活概率 + 风险 + 杂交建议
   ↓
⑤ 切到「生态报告」→ 一键导出 SVG/PNG 「观点进化图谱」 → 可发回知乎形成二次讨论
   ↓  全程无需登录即走完主路径
⑥ 点顶栏「我的观点画像」→ 授权知乎账号 → 读本人公开创作 → 看到「你是 XXX 型物种」
```

 知乎热榜     知乎搜索    问题回答/全站搜索     知乎直答         用户数据接口
 hot_list    zhihu_search  question_answers   zhida-thinking   创作/关注/收藏夹
                           global_search       -1p5            收藏夹内容/近期收藏

### 3.2 数据层：双通道 + 双抽样合并

知乎官方**没有**「问题 ID → 回答列表」接口。本项目踩到了两个**文档未记载**的端点（来自 `/api/v1/quota` 暴露的能力清单）：

- **`question_answers`**：传问题 URL，直取该问题下的真实回答（10–15 条），但**不返回赞同数**。
- **`global_search`**：全站搜索带赞同数，**能精确命中同一问题**（问题 ID 在 `Url` 里带出）。

**关键工程取舍**：这两个端点返回的不是同一批数据，而是同一问题的**两份独立抽样**（answer id 永不重合，最长公共子串实测交集为 0）。所以不是「关联」，而是**合并**——把两份抽样都作为物种植入：

```
mergeSameQuestion(answersItems, sameQuestionItems)
  → answer 数 10 + global 数 3 → 总物种池 13 条
  → question_answers 贡献成规模回答（votes=null，按热序近似）
  → global_search 贡献带 VoteUpCount 的少量回答（votes 真实）
  → 返回体如实附 enrichment.enriched / total / fromAnswers / fromGlobalSearch
```

合并后按显式三级键排序：都有数据→按赞同数降序；一方有数据→排前；都无数据→保持来源顺序。**没有真实赞同数的物种，UI 上加「虚线内环」与「按热序近似」标注，绝不编造数字**。

预构建缸效果对比（12 缸合计）：

| 指标 | 旧 LCS 富化方案 | 现 merge-two-samples |
|---|---:|---:|
| 总物种数 | 90（9 缸 ×10） | **144** |
| 带真实赞同数物种 | 13（14.4%） | **约 40（27.6%）** |
| 单缸物种数 | 固定 10 | 10–15（按数据量） |

### 3.3 智能层：本地可解释标注器 v2 + 直答分而治之

#### 我们的核心工程教训

最初的设计把知乎直答当作「输出 JSON 的分类器」，给系统提示词要求严格吐 `[{stance, strategy, summary}]`。

**实测结果：直答完全忽略格式指令**——它是一个问答/检索产品，会从输入里识别知乎问题，返回带检索来源的长篇回答。结果 40 个物种被清一色标成「中立·数据论证」，可视化成一片灰圆点，**而系统毫无察觉**。

**重构：按能力重新分工，绝不用 AI 做它不擅长的事**。

| 通道 | 做什么 | 用什么 | 额度消耗 |
|---|---|---|---|
| **A. 逐条标注** | 每条回答的立场 × 生存策略 | **本地可解释标注器 v2**（词典 + 句法规则 + 问题类型先验） | **0** |
| **B. 整缸综述** | 「这个问题下有哪几派、各靠什么立住」 | **知乎直答** `zhida-thinking-1p5`，自然语言提问不加格式约束 | 1 次/缸，永久缓存 |
| **C. 放生点评** | 「这条草稿会遭到哪些反驳」 | 知乎直答，仅生成点评文字，不影响数值 | 1 次/次，可降级 |
| **D. 自我画像** | 读用户公开创作分析其生态位 | 复用本地标注器（按用户问题内容标注） | 0 |

#### 标注器 v2：四条从失败里长出来的硬约束

1. **「未识别」作为显式兜底类**（不再用「数据论证」兼作 fallback）。
   零证据的短回答被如实归入「未识别」——能在视觉上立刻分辨「识别的」与「判不了」，而不是混进「数据论证」假装专业。
   视觉上以「虚线外描边 + 圆内留空 + 图例标注」三重信号表达。

2. **平局按证据条数决出**（不再静默判给数据论证）。
   平局时改看独立证据条数——命中 2 个不同特征的「抖机灵」比命中 1 个门控从句的「数据论证」更可信。

3. **立场 / 置信度 / 证据三字段一致性**。
   立场被强制退回中立的路径必须同步把 confidence 与 evidence 归零——不再出现「stance=中立 但 confidence=0.6」的自相矛盾返回。

4. **分布健康检查（独立告警通道）**。
   ≥50% 物种落入「未识别」时主动挂出告警——「模型承认看不懂」比「优雅地全标成数据论证」更可信。

#### 词典扩充

话题无关的通用中文修辞进入词典：
- 立场侧：`不要信 / 伪史论 / 所谓的 / 吹捧 / 洗白 / 翻译一下就是` 等「拆穿叙述」用语
- 反讽侧：夸张褒扬、引号褒义+否定、句尾反问求认同
- 策略侧：新增**推理性论证**特征组（`不在于A而在于B`、分点连接词、因果连接词）——识别「一个数字都没有但靠逻辑推进」的数据论证

#### 两通道互相印证

直答说「这个问题下有 4 派」，本地标注器逐条统计也得到 4 类——两个完全不同的方法得到一致结论，比单一来源的断言可信得多。

### 3.4 模拟层：透明存活概率公式

放生实验的存活概率**不是让模型随口给一个数**，而是一个公开可复算的规则模型（公式直接展示在界面上）：

```
P = 100 × ( 0.35 × 策略蓝海度      // 1 − 同策略物种占比
          + 0.25 × 立场差异化      // 1 − 同立场物种占比
          + 0.20 × 权威压力缓冲    // 缸内最高权威等级的压制
          + 0.20 × 互动基础度 )    // 缸内评论热度的边际收益
```

同时输出：
- `suppressedBy`：当前生态中同立场最高能量物种（如「反对立场的高赞回答（280 赞同，…）」）
- `risks`：策略红海警告 / 立场密集警告 / 蓝海优势识别
- `advice`：可执行的改写建议（「开头加入 30 字以内的真实个人经历」「第二段补充一个可验证的数据或来源」）

**用户可以不同意这个模型，但可以看懂它。** 直答点评（aiComment）独立附加在卡片下方，点评失败不影响数值。

### 3.5 治理层：五道额度闸 + 预构建

校园季试用额度远小于公开文档标称值，实测：

| 能力 | 文档 | 实测日额度 |
|---|---:|---:|
| 知乎直答 | 100 | **2** |
| 知乎热榜 | 100 | **2** |
| 知乎搜索 | 5,000 | **10** |
| 问题回答 | 未记载 | **10** |
| 用户数据 | 1,000 | 充裕（OAuth 画像用） |

在这个约束下任何「每次交互都实时调 API」的设计都会在评审当天当场失败。本项目的五道闸：

1. **结果缓存**：热榜 12h / 生态缸 24h / 问题回答 6h / 搜索 6h / 全站搜索 6h / 放生 1h / 画像 30 分钟
2. **并发去重**：同 key 并发只发一次上游调用（防双击、防前端重试双倍消耗）
3. **磁盘持久化**：生态缸缓存 + 热榜快照落盘，服务重启不丢已用额度换来的数据
4. **直答双层守卫**：本地日计数 + 服务端余量确认（额度查询本身免费）
5. **降级链**：热榜耗尽 → 历史快照（标注 snapshot）；直答不可用 → 纯规则模型；问题回答失败 → 搜索汇聚；赞同数无法匹配 → 「按热序近似」角标。**每一级降级都在界面上如实说明**

外加**预构建缸**：把热榜 13 个高热度问题的生态缸提前用额度换好，随数据卷挂载。**评委点这些问题零额度、秒开**，是 Demo 当天的最大保险。

### 3.6 标注证据：可解释从缺点变成卖点

每个标注都可展开看「凭什么这么判」——命中词 + 权重 + 按行内最大值归一的细条。
例：判为「反讽」是因为同时命中了「学会了」「支个招」「遥遥领先」三个反语特征。

**一个能被追问「你凭什么这么判」的模型，在知识产品里比一个黑箱 LLM 更有说服力。**

## 五、适配知乎社区的场景价值（本节是 40% AI 场景价值权重的核心论证）

**为什么必须依托知乎社区？** 因为这个产品的分析对象是**知乎问答的观点生态结构**——换一个平台都不成立。这是它与「恰好用了知乎数据的工具」的根本分野。

### 5.1 对象就是知乎本身

知乎是中国最大的中文问答社区，长期沉淀的「问题-回答」结构让观点竞争变得**可观察、可拆解、可复演**：
- 一题多答 → 物种多样性的天然条件
- 赞同数排序 → 能量值的天然信号
- 评论区精选 → 共生与竞争的天然证据
- 热榜 → 气候突变的天然场景
- 用户公开创作 → 个人生态位的天然数据源

**观点进化缸不创造新的内容生态，而是把知乎已有的「答案之上看不见的竞争」第一次可见地呈现出来。**

### 5.2 产出回流社区

「观点进化图谱」长图带原问题链接与数据来源水印，**设计初衷就是发回那个问题下形成二次讨论**——

- 创作者发完自己的回答后，把图谱当作「我的回答为什么这样」的自证长图
- 围观者把图谱当作「这个问题下其实有几派在打」的科普图
- 内容研究者把图谱当作「知乎生态位」的素材

**产品的输出本身就是社区内容**，而不是「用过即弃的工具产物」。

### 5.3 对创作生态是正向引导

放生实验给的**是表达建议**（「加一段个人故事」「补一个可验证的数据源」），引导用户把回答写得更扎实，**而不是更会蹭**。

这与知乎社区「认真、专业、有温度」的调性一致——
- 给出「策略蓝海度」会激励作者尝试稀缺角度，而非复制已有的爆款
- 给出「立场差异化」会鼓励独立思考，而非盲目站队
- 给出「杂交建议」会促进叙事方式的多样性，而非单一模板

### 5.4 只读、不打扰，遵守开放平台使用规范

- **零写操作**：不发布、不评论、不关注、不修改——全程只读
- **五道缓存闸**：把「直答 2 次/日」撑成评委可以随便点的 Demo
- **不批量爬取**：每个查询都是用户主动触发的单次请求
- **无自动发布**：放生实验是模拟预测，从不替用户真实提交

### 5.5 对官方 AI 能力的正确使用姿势

我们用直答做「这个问题下有哪几派观点、各靠什么立住」这类**需要检索与归纳的开放式问答**——

**不是把它当廉价分类器**（它不是，也不擅长做结构化 JSON 输出），
**而是让它在擅长的领域里发挥**（它主动给出派系名 + 代表观点 + 说服方式 + 优势结论，还标注检索来源）。

这也是对社区官方 AI 能力的「**用对地方**」——既展示了理解，又不滥用。

### 5.6 与赛道「知识炼金场」的契合

官方对「知识炼金场」的描述：
> 「观点提炼、观点比较、信息整理与内容共创，帮助用户建立理解，形成判断」

观点进化缸**逐项命中**：
- ✅ **观点提炼**：每条回答→立场 + 生存策略 + 关键词命中证据
- ✅ **观点比较**：立场分布 + 策略分布 + Top 3 排行 + 共生/竞争连线
- ✅ **信息整理**：生态缸 + 时间轴 + 干预推演 + 透明概率公式
- ✅ **内容共创**：可分享的「观点进化图谱」长图
- ✅ **建立理解**：从「为什么这条回答能赢」到「平台规则如何塑造观点」
- ✅ **形成判断**：用户放生一段自己的草稿，预演一次会得到什么反馈

## 七、我的观点画像：从「围观知乎」到「看懂自己」的闭环

这是本次黑客松的**加分项**：把同一套「立场 × 生存策略」模型从分析**别人**延伸到分析**用户自己**。

用户授权后，本项目读取用户最近的公开创作（`/api/v1/user_data` 系列），复用标注器 v2 标注每条作品，统计：
- 立场分布（六类 + 中立兜底）
- 策略分布（六类 + **未识别**作为第七类单独显示，不并入其他类伪装识别率）
- Top 5 样本（按置信度排序，每条可展开看判定证据）
- 「未识别条数」显式提示（不是错误，是诚实）

支持新号空态：「你的公开创作还不够做画像」——**空状态是正常结果，不是报错页**。

30 分钟按会话缓存：评委在自己账号上点两次，第二次命中缓存，不消耗额度。

## 八、诚信声明（边界写死在界面上）

做这个产品最容易越界的地方，是拿推演当史实。我们把边界写在界面上：

| 边界 | 落实方式 |
|---|---|
| 演化时间轴是 AI 重建，不是历史 | 时间轴顶部固定徽标「**AI 演化重建 · 非历史记录**」；产品说明中主动声明 |
| 放生结果不是平台真实数据 | 报告角标「**AI 模拟预测**」；概率公式公开可复算 |
| 模型不确定时显式说明 | 标注置信度低于阈值显示「低置信」角标；「未识别」作为可见的兜底类，不冒充「数据论证」 |
| 降级如实告知 | 额度耗尽 / 搜索无结果 / 赞同数无法匹配，界面都显式说明当前降级状态 |
| 演示模式使用虚构作者名 | 醒目标徽「演示数据集 · 未接入开放平台」 |
| 主动放弃虚假能力 | 原方案中的「折叠化石层」「作者粉丝数」「收藏数」因官方 API 不提供而**主动移除**，不做无法溯源的声称 |

合规自查：`tools/compliance-check.mjs` 以脚本方式机械校验「凭证零泄漏 / 三处诚信标注在位 / 依赖未偷偷变更」，不靠人眼复核。
